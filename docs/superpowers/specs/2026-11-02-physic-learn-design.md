## 1. เป้าหมายและสิ่งที่ผู้ใช้ยืนยัน

สร้างเว็บภาษาไทยสำหรับผู้เรียนคนเดียว ใช้ได้ทั้งมือถือ แท็บเล็ต และคอมพิวเตอร์ เรียนต่อจากเครื่องอื่นได้โดยความคืบหน้าไม่หาย ผู้ใช้เลือกแนวทางเว็บส่วนตัวผ่าน Sites และบัญชี ChatGPT แล้วในวันที่ 2 พฤศจิกายน 2026

เว็บมีสองโหมดหลัก:

- **เรียน** แยกเป็นเรียนทีละขั้นพร้อม infographic และเรียนผ่านเกม เช่น จับคู่สูตรกับสถานการณ์
- **ทำข้อสอบ** ใช้แนวโจทย์ใน PDF สร้างโจทย์ตัวเลขใหม่ เก็บคำตอบ คะแนน และเฉลยของโจทย์ชุดนั้นไว้ทบทวน

เนื้อหาแบ่งเป็นด่าน เชื่อมบทเรียน เกม และการทดสอบในด่านเดียวกัน ใช้สกิล brainstorming ของ Superpowers, design-taste-frontend, กติกา Lucide / Simple Icons, Impeccable และ Playwright ตามคำขอ

สิ่งที่ยืนยันแล้วคือรูปแบบการใช้งานและแนวทางโฮสต์ ส่วนรายละเอียดค่าเริ่มต้นด้านล่างเป็นข้อเสนอของผู้พัฒนาเพื่อให้ตรวจครั้งเดียว ไม่อ้างว่าเป็นสิ่งที่ผู้ใช้อนุมัติแล้ว

## 5. ประสบการณ์ใช้งาน

### หน้าเริ่มต้นและแผนที่ด่าน

แสดงสิ่งที่จะเรียนต่อเป็นการกระทำหลัก มีความคืบหน้า 4 บท ด่านที่เรียนล่าสุด และรายการข้อที่ยังผิด ใช้ค่าจากข้อมูลจริง บัญชีใหม่เริ่มที่ศูนย์ ด่านที่ยังไม่ผ่านดูบทนำและย้อนทบทวนได้

ทุกด่านมีสถานะ ยังไม่เริ่ม / กำลังเรียน / พร้อมทดสอบ / ผ่านแล้ว เส้นทางแนะนำเรียงด่าน แต่ผู้ใช้เลือกบทที่ต้องการทบทวนได้ ไม่บังคับทำคลื่นให้ครบก่อนเปิดเสียง

### เรียนทีละขั้น

บทเรียนย่อยประมาณ 3–6 ขั้นตามเนื้อหา แต่ละขั้นมีแนวคิดหนึ่งเรื่อง ภาพที่สอดคล้องกับสูตร ตัวแปรพร้อมหน่วย และตัวอย่างสั้น ผู้ใช้กดย้อนกลับหรือดูสูตรได้เสมอ เก็บตำแหน่งที่อ่านค้างแยกจากผลสอบ

Infographic วาดด้วย SVG/HTML จากข้อมูลเดียวกับสูตร ปรับค่าแล้วภาพและตัวเลขเปลี่ยนตรงกัน เช่น ความถี่กับความยาวคลื่น ตำแหน่งริ้วสว่าง หรือระยะวัตถุกับภาพ รองรับปุ่ม/ช่องกรอกควบคู่ slider และมีข้อความอธิบายแทนภาพ หยุด animation และเคารพ reduced motion

### เรียนผ่านเกม

มีเกมจับคู่ 4–6 คู่ต่อรอบ เช่น สูตร ↔ สถานการณ์ ตัวแปร ↔ หน่วย หรือภาพ ↔ ชนิดปรากฏการณ์ ปุ่มแตะเลือกสองฝั่งเป็นวิธีหลัก มือถือและคีย์บอร์ดใช้ได้ ไม่พึ่งลากวางอย่างเดียว

ตอบผิดอธิบายเหตุผล ไม่ตัดสิทธิ์เรียน เล่นใหม่ได้ และเก็บสรุปผลเพื่อแนะนำหัวข้อที่ควรทบทวน เนื้อหาทุกด่านต้องมีเกมที่เกี่ยวข้อง ไม่ใช้เกมจับคู่สูตรเดียวซ้ำแทนทุกเรื่อง

### ทำข้อสอบ

มีแบบทดสอบท้ายด่านและข้อสอบรวม เลือกบท จำนวนข้อ และเปิด/ปิดจับเวลาได้ ค่าเริ่มต้น: ท้ายด่าน 5 ข้อ; ข้อสอบรวม 20 ข้อไม่จับเวลา หลีกเลี่ยงแม่แบบซ้ำภายในชุดเมื่อมีแม่แบบเพียงพอ

ท้ายด่านผ่านเมื่อถูกอย่างน้อย 80% เก็บคะแนนสูงสุดและผลแต่ละครั้งแยกกัน การอ่านเฉลยหรือเล่นเกมอย่างเดียวไม่ทำให้ผ่านด่าน อนุญาตข้ามการเรียนไปลองสอบได้เพราะเป็นเว็บทบทวนส่วนตัว

ระหว่างสอบบันทึกคำตอบและข้อปัจจุบัน ไม่แสดงเฉลยจนส่งชุดหรือยืนยันยุติชุด ข้อสอบที่จับเวลาใช้เวลาหมดอายุจากเซิร์ฟเวอร์ การ reload หรือเปลี่ยนเครื่องไม่เริ่มเวลาใหม่ เมื่อหมดเวลาส่งคำตอบที่บันทึกทันแล้วอย่างเดียวและแจ้งสิ่งที่ยังไม่ซิงก์

หลังส่งแสดงคะแนน คำตอบของผู้ใช้ คำตอบที่ถูก วิธีคิดทีละขั้น สูตร แทนค่า หน่วย จุดพลาด และหน้าต้นฉบับ มีปุ่มฝึกใหม่ตัวเลขใหม่จากหัวข้อเดียวกัน ประวัติเดิมยังเปิดดูได้ครบแม้ generator ถูกอัปเดต

## 6. การสร้างโจทย์และความถูกต้อง

ทำทะเบียนโจทย์เดิมครบ 70 ข้อ แต่ละข้อมี source chapter, page, number, concept, lesson, template ID และสถานะการตรวจ เพื่อป้องกันการลืมข้อที่พึ่งภาพหรือข้อท้ายไฟล์

- **ข้อคำนวณ:** แปลงเป็นแม่แบบที่สุ่มเฉพาะค่าที่อนุญาต แล้วคำนวณคำตอบ ตัวลวง ภาพ และเฉลยใหม่จากชุดค่าเดียวกัน
- **ข้อเชิงแนวคิด:** สลับสถานการณ์ รูปภาพ ตัวเลือก หรือการจัดวางที่ยังคงความหมาย ไม่ฝืนเปลี่ยนตัวเลขให้โจทย์ไม่มีเหตุผล
- **ข้อพึ่งกราฟ/แผนภาพ:** สร้างรูปจากพารามิเตอร์จริงพร้อมแกนและหน่วย ไม่แก้แค่ข้อความข้างรูปเก่า
- **ข้อกำกวม/ผิดพิมพ์:** บันทึกไว้ในทะเบียนและแก้เป็นโจทย์ดัดแปลงที่ตรวจแล้ว อธิบายจุดต่างจากต้นฉบับก่อนนำเข้าข้อสอบ ไม่อ้างว่าตรวจครบทั้ง 70 ข้อจนกว่าทุกข้อผ่านเกณฑ์

แม่แบบแต่ละอันมีช่วงค่า เงื่อนไขทางฟิสิกส์ ระบบเครื่องหมาย หน่วย ความละเอียดการปัด และเงื่อนไขที่ใช้สูตรประมาณ เช่น มุมเล็ก ต้องไม่เกิดหารด้วยศูนย์ ค่า arcsin เกินโดเมน จำนวนริ้วที่เป็นไปไม่ได้ หรือความเร็วดอปเพลอร์ผิดขอบเขต

คำนวณภายในด้วยค่าที่ยังไม่ปัด ปัดเฉพาะการแสดงผล คำตอบที่เห็นในเฉลยต้องตรงกับช้อยส์ที่ถูกหลังปัด และตัวเลือกต้องไม่ซ้ำกันหลังจัดรูปแบบ ตรวจรับคำตอบเชิงตัวเลขด้วย tolerance ที่ระบุในโจทย์ ใช้ระบบ SI ภายในและแปลงหน่วยอย่างชัดเจน

สร้างและตรวจข้อสอบฝั่งเซิร์ฟเวอร์ ไม่ส่งเฉลยหรือ flag ตัวเลือกที่ถูกไปกับ payload ระหว่างสอบ ชุดที่สร้างสำเร็จต้องถูกเก็บก่อนเปิดให้ตอบ เพื่อไม่ให้ reload แล้วเลขเปลี่ยน หากสุ่มไม่ผ่านเงื่อนไขหลัง retry ที่จำกัด ให้ใช้ชุดพารามิเตอร์สำรองที่ตรวจแล้ว

บทเรียนตัวอย่างและเกมอนุญาตแสดงคำอธิบายทันที ไม่จำเป็นต้องซ่อนเหมือนข้อสอบ

ไม่ต้องเรียก AI ระหว่างใช้งานประจำวัน ตัวสร้างโจทย์และเฉลยเป็น deterministic functions ที่ทดสอบได้ การตอบใหม่ของชุดเดิมไม่สุ่มตัวเลขใหม่ เก็บ templateVersion และ seed/parameters รวมถึง snapshot ของข้อความ รูปแบบรูป ตัวเลือก คำตอบ และเฉลยในประวัติที่เซิร์ฟเวอร์ป้องกันไว้

## 7. ความคืบหน้าและการซิงก์หลายอุปกรณ์

Sites เป็นเว็บส่วนตัวสำหรับเจ้าของ ใช้ตัวตน ChatGPT เดิมบนแต่ละเครื่อง เก็บข้อมูลใน D1 ฝั่งเซิร์ฟเวอร์ อุปกรณ์ใหม่โหลดข้อมูลที่บันทึกแล้ว ไม่ใช้ localStorage เป็นแหล่งข้อมูลหลัก

เก็บสถานะบันทึกเป็น กำลังบันทึก / บันทึกแล้ว / ออฟไลน์หรือบันทึกไม่สำเร็จ พร้อมเวลาแสดงที่เข้าใจได้ เมื่อไม่มีเครือข่าย อ่านหน้าที่โหลดไว้ต่อและเก็บ draft การตอบในเครื่องได้ แต่ต้องบอกว่าข้อมูลยังไม่ขึ้นเซิร์ฟเวอร์ ไม่สร้างข้อสอบใหม่หรือยืนยันส่งสำเร็จแบบออฟไลน์

ดึงข้อมูลล่าสุดเมื่อเปิดเว็บ กลับมาโฟกัสหน้า หรือกลับมาออนไลน์ และระหว่างมีชุดข้อสอบที่เปิดอยู่ บันทึกการเลือกคำตอบโดยเร็วพร้อมแสดง pending state หน้าเรียน debounce การบันทึกตำแหน่งได้

แบบจำลองข้อมูลเสนอ:

| ข้อมูล | หน้าที่ |
| --- | --- |
| identity / user key | อ้างอิง stable user ID ที่ Sites ยืนยัน ห้ามรับ user ID ตามใจจาก browser |
| lesson_progress | lessonId, stepId, completed steps, contentVersion, revision, เวลาอัปเดต |
| game_runs | UUID ของรอบ, ด่าน, ผลและข้อผิดพลาด โดยไม่ทับรอบก่อน |
| exam_attempts | UUID, บท/ด่าน, question snapshots, คำตอบ, สถานะ active/submitted/abandoned, deadline, คะแนน, revision |
| exam_answer_events | event ID และลำดับ revision เพื่อ deduplicate การส่งซ้ำ |
| stage_progress | สรุปจากบทเรียน เกม และข้อสอบที่เซิร์ฟเวอร์ยอมรับ ไม่เชื่อคะแนนที่ browser ส่งมา |

การตอบพร้อมกันสองเครื่องใช้ revision ตรวจชนกัน การเขียนบน revision เก่าตอบ conflict และโหลดฉบับล่าสุด พร้อมรักษาร่างในเครื่องให้เลือกใช้ต่อ ไม่ทับคำตอบเงียบ ๆ หรือรวมคำตอบคนละข้อสอบเข้าด้วยกัน รอบเกมและผลสอบคนละรอบเก็บเพิ่มได้ทั้งคู่ ตำแหน่งอ่านใช้เวลาเซิร์ฟเวอร์ ส่วนขั้นที่เรียนจบรวมแบบ union เพื่อไม่ลดความคืบหน้า

การส่งชุดเป็นธุรกรรมที่ทำซ้ำได้โดยไม่คิดคะแนนซ้ำ submitted แล้วแก้คำตอบไม่ได้ คะแนนสูงสุดและด่านที่ผ่านแล้วไม่ลดเพราะเปิดจากอุปกรณ์ที่ข้อมูลเก่า ทุก endpoint ตรวจตัวตนและเจ้าของข้อมูลฝั่งเซิร์ฟเวอร์

เก็บเวลา UTC และแสดงวันเวลาตาม Asia/Bangkok ไม่มีระบบรีเซ็ตประวัติทั้งหมดในรอบแรก

## 8. หน้าตาและการเข้าถึง

ข้อเสนอภาพรวมคือสมุดแล็บฟิสิกส์ที่อ่านสบาย: พื้นอุ่นอ่อน ตัวอักษรเข้ม ใช้สีเน้นกับคลื่น รังสี และสถานะที่มีความหมาย มีกราฟและภาพประกอบเป็นองค์ประกอบหลัก ไม่ใช้ dashboard ที่เต็มด้วยตัวเลขตกแต่ง

- หน้าแผนที่และทำข้อสอบเน้นความชัดของงาน; หน้าเรียนเน้นอ่านและเข้าใจ; เกมเพิ่มการตอบสนองโดยไม่รบกวนเนื้อหา
- อักษรไทยเลือกฟอนต์ที่รองรับไทยและสูตร อ่านได้ตั้งแต่จอ 360px จน desktop ไม่บังคับแนวนอน
- Lucide สำหรับไอคอน UI, Simple Icons เฉพาะโลโก้แบรนด์จริงที่มีเหตุให้แสดง ไม่ใช้ emoji แทนปุ่มหรือวาดโลโก้แบรนด์เลียนแบบ
- ค่าทางคณิตศาสตร์แสดงด้วย renderer ที่รองรับสมการและ accessible text การตัดบรรทัดต้องไม่ทำให้หน่วยหรือดัชนีเปลี่ยนความหมาย
- ปุ่มแตะสะดวกอย่างน้อยประมาณ 44px, focus เห็นชัด, keyboard navigation, labels จริง, contrast อ่านได้ และไม่ใช้สีอย่างเดียวบอกถูกผิด
- มี loading, empty, offline, save error, conflict และ retry ที่ใช้งานได้จริง
- ไม่มี leaderboard, สังคม, ชีวิตจำกัด, โฆษณา หรือค่าใช้จ่ายใน flow การเรียน

รายละเอียดสี ฟอนต์ ระยะ และ motion เป็นหน้าที่ผู้พัฒนาภายใต้ Taste และ Impeccable; infographic เป็น SVG/HTML ที่ผูกค่าจริง ไม่ต้องใช้รูป AI เพื่อแทนแผนภาพวิทยาศาสตร์

## 9. ขอบเขตและสิ่งที่ไม่ทำในรอบนี้

รอบแรกครอบคลุมทั้ง 4 บทและทะเบียนโจทย์ 70 ข้อ รวมเกมและบทเรียนทุกด่าน การซิงก์จริง และเว็บส่วนตัวที่ deploy แล้ว ไม่หยุดที่ mockup หรือบันทึกข้อมูลในเครื่องอย่างเดียว

ไม่ทำหลักสูตรนอก PDF, ระบบหลายผู้เรียน/ห้องเรียน, แชตติวเตอร์ AI, ระบบจ่ายเงิน, offline-first เต็มรูปแบบ หรือแอป native สามารถอ่านเอกสารต้นฉบับในเว็บได้ แต่ตัวเว็บต้องอ่านรู้เรื่องด้วยตัวเองโดยไม่บังคับเปิด PDF

ไม่เผยแพร่เว็บเป็น public และไม่เปลี่ยนสิทธิ์ของ repo ที่ผู้ใช้สร้างไว้ เก็บ secrets เฉพาะระบบ runtime ไม่ลง GitHub

## 10. เกณฑ์ตรวจรับ

1. ทะเบียนจับคู่โจทย์ 70 ข้อกับด่านและหน้า PDF ครบ รวมคลื่นข้อ 19–20 หน้า 58 และตรวจข้อที่พึ่งภาพก่อนใช้งาน
2. ทุกด่านเปิดเรียนทีละขั้น เล่นเกม และสอบได้ มีคำอธิบายเมื่อเล่นผิดและเฉลยหลังสอบ
3. ทดสอบ generator ทุกแม่แบบหลาย seed รวมขอบเขตและการแปลงหน่วย เทียบกับตัวอย่างที่คำนวณตรวจแยกอย่างน้อยหนึ่งกรณีต่อแม่แบบ ไม่ใช้ตัว generator เป็น oracle ของตัวเอง
4. ตัวเลข คำตอบ ช้อยส์ ภาพ และเฉลยของ variant เดียวกันสอดคล้องกัน เปลี่ยน seed แล้วได้ชุดใหม่ในช่วงที่กำหนด
5. ทดสอบ server-side authorization, idempotent submit, stale revision, คะแนนและการผ่านด่านที่ client ปลอมไม่ได้
6. Playwright ทดสอบเรียนต่อ เกมจับคู่ การทำ/ส่งข้อสอบ ดูประวัติ reload แล้วเลขไม่เปลี่ยน และบันทึกผิดพลาดแล้ว retry
7. ทดสอบสอง browser contexts กับฐานข้อมูลเดียว: เรียนหรือส่งสอบจาก A แล้วเปิด B เห็น progress; จงใจแก้ชุดเดียวกันพร้อมกันแล้วเกิด conflict ที่แก้ต่อได้; ห้ามใช้การคัดลอก localStorage แทนการทดสอบซิงก์
8. ตรวจ desktop, tablet และมือถืออย่างน้อย 390px รวม keyboard, reduced motion และไม่มี horizontal overflow ของหน้าหลัก
9. build และ migration ผ่าน; source ใน GitHub ตรงกับเวอร์ชันที่นำไป deploy; บันทึกผลตรวจจริงและข้อจำกัดที่ยังทดสอบไม่ได้

## 11. การใช้สกิลและการส่งมอบ

- Superpowers brainstorming: เอกสารนี้และ builder check ก่อนขออนุมัติ หลังอนุมัติจึงอ่าน writing-plans และทำแผน implementation
- design-taste-frontend: ใช้แนวทาง app screens สำหรับโครงเว็บ และตรวจภาพจริงหลายขนาด
- Lucide / Simple Icons: ปฏิบัติตามกติกาไอคอนที่ผู้ใช้ระบุ
- Impeccable: จัดบริบทผลิตภัณฑ์และระบบภาพ ตรวจความอ่านง่าย การปรับจอ และ polish
- Playwright: ใช้เครื่องมือทางการของ Microsoft ตรวจ interaction และ flow จริง รวม multi-context sync
- Sites: identity, D1, source packaging และ deploy ส่วนตัวตาม workflow ของแพลตฟอร์ม

ตัว implementation จะเพิ่ม README วิธีรัน ทะเบียนเนื้อหา ผลตรวจ และลิงก์เว็บจริงใน repo นี้ ไฟล์ PDF เดิมคงอยู่ตามที่ผู้ใช้อัปโหลด

### สถานะการตัดสินใจ

- **ผู้ใช้เลือกแล้ว:** เว็บส่วนตัวผ่าน Sites; ใช้บัญชี ChatGPT เดิม; เนื้อหาจากไฟล์ใน repo; ใช้สกิล 5 กลุ่มที่ระบุ
- **ข้อเสนอให้ตรวจพร้อมแบบ:** 20 ด่าน, เกณฑ์ผ่าน 80%, ท้ายด่าน 5 ข้อ, ข้อสอบรวมค่าเริ่มต้น 20 ข้อไม่จับเวลา, สอบข้ามด่านได้, เฉลยหลังส่งชุด, ไม่พึ่ง AI ระหว่างเรียน
- **ผู้พัฒนาตัดสินใจได้:** โครงสร้าง component, schema ที่ละเอียด, วิธีแบ่ง lesson ย่อย, ชื่อสี/ฟอนต์, library แสดงสูตร, ช่วงตัวเลขต่อแม่แบบ และชื่อ route ตราบใดที่ผ่านข้อกำหนดนี้
- **ยังไม่อนุมัติ:** เอกสารแบบฉบับนี้และการเริ่ม implementation ตามแบบ
